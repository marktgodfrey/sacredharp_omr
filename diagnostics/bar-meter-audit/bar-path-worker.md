# Bar and meter code-path audit

Scope: read-only audit of current `source_reflow.py`, `run_proposal_rhythm_recovery.py`, writer, and latest `final-0318d4f06bb9` trace shape. No applicable `AGENTS.md` was found. Source meter glyph inventory is out of scope.

## Concrete code-path findings

- **Ordinary system reflow deliberately inherits the old shared cut lengths.** `reflow_transform` chops each source voice using `original_pass['cuts'][m]`, tracks each event's original layout bar, and carries lengths into merged columns (`source_reflow.py:88-103, 117-123`). Its docstring explicitly says inherited cuts retain existing segmentation errors (`source_reflow.py:78-84`). Result: after a grouping repair, parallel staff/bar placement can improve while a wrong or irregular original global cut still clips a reflowed voice.
- **The source segmentation path runs only when the collapsed-bar heuristic fires.** It requires a bar wider than 12 staff spaces and at least two spatially separate, high-confidence beat-zero notes (`source_reflow.py:19-35`); it is invoked only when grouping changed and that evidence is nonempty (`run_proposal_rhythm_recovery.py:98-108`). Thus other incorrect source bar boundaries remain untouched by design.
- **The candidate segmentation path clears nonopening key/time/clef readings.** For every new bar after the first, `segment_source_bars` sets the bar token's `key`, `time`, and `clef` values to `None` (`source_reflow.py:50-63`). Since `_bar_state` applies non-null bar-head readings as state changes (`copisteria/src/copisteria/write.py:313-322`), printed key/time changes that land on such a resegmented bar are dropped from the state. This is a concrete loss mechanism, though whether a particular source change is lost depends on the resulting segmentation and glyph-to-bar assignment.
- **Cutting is destructive to emitted events.** `_chop` drops events starting at/after the cut and may truncate plain notes/rests that extend past it (`write.py:1045-1048`); writer applies the shared column cut to every staff voice (`write.py:1421-1429`). The source reflow input events have already been chopped before reassignment (`source_reflow.py:99`). The current selected-cut source therefore affects both reflow payload and final output.

## Risks / not established as actual failures

- Final cuts can be computed from the reflowed selected events: the transform returns its merged inherited lengths (`source_reflow.py:105-140`), and `write` uses those returned `selected_bar_ends` instead of normal `_column_lengths` voting (`write.py:1367-1372, 1421-1428`). For segmentation, writer instead derives lengths with `_column_lengths` from its candidate bars (`write.py:1013-1033`). I did not establish specific pages where these resulting cuts are wrong.
- Time/key propagation is staff-local and stateful in `_bar_state`, but output attributes are selected from the first staff in each part's measure (`write.py:1319-1342, 1463-1492`). This creates a risk of divergent staff changes not being represented at measure level; no specific failing page was proven here.

## What latest traces say about final cuts

The latest trace example `experiments/proposal-rhythm/final-0318d4f06bb9/predictions/1911-s0168-funeral-thought.trace.json` contains `fixed_column_cuts`, `fixed_opening_meter`, `writer`, and `rhythm_recovery_details`. `fixed_column_cuts` is inherited from the input proposal trace because the runner writes `{**t, **serialize_reading(rd), 'writer': emitted, ...}` (`run_proposal_rhythm_recovery.py:137-140`); it describes the previous frozen pass, not final post-reflow selection. The runner's in-memory `selected_pass['cuts']` is used for reflow and opening meter (`run_proposal_rhythm_recovery.py:108-124`) but is not serialized. The final `writer.emitted` records event value and `measure_number`, not column/bar cut lengths (`reader_trace.py:52-67`). Final traces serialize selected layout symbols/staves/systems but no selected cut vector (`reader_trace.py:77-85`). Therefore **no trace field directly and authoritatively records final selected cuts**; the old `fixed_column_cuts` should not be cited as final after reflow/segmentation.

Recommended next step: preserve an explicit final selected-cut vector in a future trace schema before using traces to diagnose clipping. Alternative: audit specific suspect pages by replaying their saved final layout/events against source bar lines.
